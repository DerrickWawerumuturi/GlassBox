# Glassbox Editorial

Visual investigations built from the weekly count of tech job ads. Not a blog, not a dashboard with paragraphs.

This is the current source of truth for Glassbox Editorial. It was adopted on 14 Oct 2026 and refined against the product, the approved prototypes and later story work. Earlier handoff material is not an active instruction set.

## The documents

| File | What it holds |
|---|---|
| `EDITORIAL_VISION.md` | why the publication exists, who it's for, how it relates to the product |
| `CREATIVE_PRINCIPLES.md` | the rules that keep stories from looking generic |
| `VISUAL_LANGUAGE.md` | what is shared with the product (fonts, tokens, chart grammar) and what each story may set for itself |
| `STORYTELLING_GUIDE.md` | the workflow: question, evidence, concepts, storyboard, prototype, build, review |
| `INTERACTION_GUIDE.md` | when interaction earns its place; motion, touch, reduced motion |
| `REFERENCE_LIBRARY.md` | annotated references: the element, why it works, what to borrow, what not to copy |
| `DESIGN_REVIEW.md` | the rubric, scored on rendered screenshots |
| `experiments/visual-concepts.md` | concepts explored, chosen and rejected, with reasons |
| `investigations/<slug>/` | one folder per story: `research.md`, `creative-brief.md`, `storyboard.md`, `implementation-notes.md` |
| `sprints/` | one record per art direction sprint: what was studied, the directions, scores from renders, the recommendation |
| `references/` | our own screenshots and the workflow diagrams. No copies of other publishers' artwork. |

Local working material stays in ignored `docs/local/`: runnable prototypes, screenshots, reference captures and distribution drafts. It is not a second source of policy.

## Rule for every editorial session

Read this file, `EDITORIAL_VISION.md`, `CREATIVE_PRINCIPLES.md`, `VISUAL_LANGUAGE.md` and the active investigation folder. Read a reference note only when the story needs it. Then, before any production code:

1. Verify the evidence (`research.md`, with traceable calculations).
2. Present three materially different concepts.
3. Get one concept approved by the founder.
4. Storyboard it, then prototype the opening, the main visual and one phone state.
5. Review real screenshots at 390px and 1280px against `DESIGN_REVIEW.md`.

The shared project rules in `AGENTS.md` apply: short, precise copy; numbers say what they count; “we show, you decide”; public pages read published data; nothing is published without the founder's approval.
