## What changed

- **Signed-in scans keep the parsed CV profile**, one row per user in the new
  `latest_cvs` table: the `ParsedQuery` (minus `notes`), file name, sha256 of
  the text, `parsed_at`, parser version. Never the PDF, never the text.
- **The agent run is two calls.** `JobRadarAgent.parse(cv_text)` is the one
  Groq call; `JobRadarAgent.match(query, preferences)` searches, ranks and
  summarises. `run` still chains them.
- **The same CV is never parsed twice.** If an upload's text hash matches the
  kept one, `/analyze` skips Groq and reuses the profile. A different CV is
  parsed and replaces the row.
- **New endpoints**, all signed-in:
  - `POST /analyze/reuse`: rescan from the kept profile. Same shape as
    `/analyze`. 404 nothing kept, 409 parsed by an older parser.
  - `GET /cv/latest`: `{file_name, parsed_at, skills, reusable}`, or 404.
  - `DELETE /cv/latest`: `{deleted: bool}`.
- `DELETE /account/data` now removes the kept profile too.
- A storage failure is logged and never costs a scan. Anonymous scans store nothing.
- Frontend: `GetLatestCV`, `DeleteLatestCV`, `AnalyzeReuse` in `lib/api.ts`.
  No UI yet.

## Needs doing before it works in production

- **Apply migration `016_latest_cv` to the production database**
  (`python -m src.database.migrate`). It has only been applied to the local
  test database. Until it is applied, `/analyze` still works (storage errors
  are caught) but nothing is kept, and `/cv/latest` and `/analyze/reuse` fail.
